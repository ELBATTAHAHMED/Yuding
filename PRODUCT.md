# Yuding

<!-- impeccable:product-schema 1 -->

## Platform
web

## Users
Travel operations staff, support operators, content moderators and administrators. The Admin console prioritizes failed refunds and booking/payment reconciliation, as confirmed by the user.

## Product Purpose
Operate travel dossiers for hotels, flights, activities, transfers and trains; resolve financial incidents, govern accounts and moderate traveler reviews.

## Operating Context
Desktop is the primary workspace. Tablet and mobile retain access to records and actions. This repository runs a sandbox/demo payment environment.

## Capabilities and Constraints
One Admin inside the existing Next.js App Router. Gateway is the only API entry. PostgreSQL-backed contracts and independent backend RBAC remain authoritative. Preserve all existing uncommitted work, legacy frontend and protected Phase 14 stash. No fabricated metrics, travel details, photos or health states.

## Brand Commitments
Official Yuding logo, restrained teal, French operational language. Cool off-white light mode and neutral charcoal dark mode. The current Admin presentation is explicitly rejected.

## Product Principles
Surface actionable incidents first. Link related entities naturally. Distinguish unavailable data from empty results. Keep technical payloads secondary.

## Accessibility & Inclusion
Keyboard navigation, visible focus, focus-managed inspectors, accessible confirmation dialogs and reduced motion.
